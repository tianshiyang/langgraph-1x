# 测试用例与期望 · 保险理赔智能审核 Agent

> 面向开发/自测。每个用例给：**ID / 前置 / 输入 / 步骤 / 期望 / 对应 FR·BR / 复习点**。
> 期望值都是**可判定的**（具体数字、具体路由、具体字段），不写"大概"。
> 规则/字段定义见 [`需求规格说明书.md`](./需求规格说明书.md)。

## 0. 测试分层

| 层级 | 测什么 | 依赖 |
| --- | --- | --- |
| L1 单元 | 测算公式、校验规则、检索、脱敏 | 纯函数/Milvus |
| L2 节点契约 | 单个节点 输入→输出 | 桩数据 |
| L3 集成(E2E) | 5 个样例案件走完整图 | 全链路(不含 Langfuse) |
| L4 HITL | 中断/恢复/四种裁决 | + checkpointer |
| L5 观测/评估 | Langfuse trace/score/回归 | + Langfuse |

## L1 单元测试

### U-1 赔付测算公式（settle，BR-6）— **最重要，必须逐项对**

| 用例 | 输入(invoice_total, social_paid, excluded, deductible, rate, remaining_sum) | 期望 payable | 说明 |
| --- | --- | --- | --- |
| U-1a | 28000, 10000, 0, 10000, 1.0, 3000000 | **8000** | Case A 主线 |
| U-1b | 180000, 50000, 0, 10000, 1.0, 3000000 | **120000** | Case B 大额 |
| U-1c | 12000, 10000, 0, 10000, 1.0, 3000000 | **0** | 免赔额以下，应赔 0 |
| U-1d | 28000, 0, 3000, 10000, 0.6, 3000000 | **9000** | 无社保60%：(28000-3000-10000)*0.6 |
| U-1e | 500000, 0, 0, 10000, 1.0, 300000 | **300000** | 保额余额封顶 |

> 断言：`settle()` 输出的 `payable` 与上表完全相等；且 `reasonable/payable_before_cap` 中间项可复算。

| 用例 | 输入 | 期望 |

## L3 集成 · 五个样例案件（E2E，走完整图，不含 Langfuse）

> 断言"最终路由 + 关键 state 值"。这五个也是 L5 回归数据集。

### E-A 小额自动直赔
- **输入**：`claim_id=CLM-A`（住院 28000，社保 10000，材料齐、非既往症、已过等待期）
- **期望**：路由 `auto_pay`；`settlement.payable==8000`；`decision.route=="auto_pay"`；`clm_claims.status→已赔付`；`result.approved_amount==8000`。
- FR：1-8,10 / BR：1-3,6,8 / 复习：主流程、Send、Command

### E-B 大额转人工(HITL)
- **输入**：`claim_id=CLM-B`（住院 180000，社保 50000）
- **期望**：路由 `human_review`；图停在 interrupt，载荷含 `payable==120000` + 明细 + 条款 + 风险；`status→待核赔`。（后续裁决见 H 系列）
- FR：1-9 / BR：6,8 / 复习：HITL、持久化

### E-C 拒赔(等待期/既往症)
- **输入**：`claim_id=CLM-C`（出险日在等待期内）
- **期望**：路由 `reject`；`policy_check.passed_waiting==False`；`decision.clause_refs` 含等待期条款号；`result.decision=="拒赔"`；`status→已拒赔`；拒赔文书引用条款。
- FR：4,8,10 / BR：4,5,8 / 复习：拒赔分支、条款匹配

### E-D 待补件
- **输入**：`claim_id=CLM-D`（缺费用清单）
- **期望**：路由 `need_more`；`validation.complete==False`，`missing==["费用清单"]`；`status→待补件`；**不进入**保单核对/测算。
- FR：3 / BR：1 / 复习：条件边、循环重入

### E-E 反欺诈转人工
- **输入**：`claim_id=CLM-E`（90 天内第 3 次 + 机构在名单 + 命中历史欺诈相似案例）
- **期望**：`fraud.risk_level=="高"`，signals 至少命中 短期多次+名单+相似欺诈三条；路由 `human_review`；interrupt 载荷 `fraud.signals` 完整。
- FR：6,8,9 / BR：7,8 / 复习：反欺诈子图、Milvus 相似检索、store 记忆

## L4 HITL 裁决（基于 E-B 挂起态 resume）

| 用例 | resume 注入 | 期望 |
| --- | --- | --- |
| H-1 approve | `{action:approve, adjuster_id:ADJ1}` | 按 payable=120000 出具；status→已赔付；记事件 actor=ADJ1 |
| H-2 adjust | `{action:adjust, amount:100000, adjuster_id:ADJ1}` | approved_amount=100000；记"差异 -20000"事件；status→已赔付 |
| H-3 reject | `{action:reject, reason:"发票存疑", adjuster_id:ADJ1}` | status→已拒赔；文书含核赔员理由 |
| H-4 return | `{action:return, reason:"需原件", adjuster_id:ADJ1}` | 回 need_more；status→待补件 |
| H-5 恢复 | 重启进程后用 claim_id 续跑 | 能从中断点继续，不重跑已完成节点 |

## L5 观测与评估（Langfuse）

> 埋点细节见 [`Langfuse埋点规范.md`](./Langfuse埋点规范.md)。这里给验收断言。

### O-1 Trace 结构
- 跑 E-A 后 UI：一个 root trace，其下有 `intake / extract / validate / policy_check / clause_match(retriever) / fraud / settle / decide / auto_pay` 对应 span；`clause_match` 是 retriever 类型且 output 含命中条款+score。

### O-2 Session 串联
- E-D 待补件后补材料再跑，两次都用 `session_id=CLM-D` → UI Sessions 里聚成一个会话。

### O-3 PII 脱敏
- E-E 含身份证的抽取输入，UI 显示 `<ID>`，无明文。

### O-4 成本
- 配好 `glm-*` 定价后，generation 成本非 0。

### O-5 LLM-as-judge（judge.py）
- 对 E-A/E-C 结论产出三维分数并写回 trace：`has_clause_basis`(BOOLEAN)、`amount_correct`(BOOLEAN)、`reason_sufficient`(NUMERIC 0-1)。
- 断言：E-A `amount_correct=True`（8000 与复算一致）；E-C `has_clause_basis=True`。

### O-6 离线回归（evaluate.py）— **对比行业标准的关键**
- 数据集 = E-A~E-E。基线跑一遍记录各案 route+payable。
- **改规则**：`deductible` 10000→15000，重跑。
- **期望差异**：E-A `payable` 由 8000 → **3000**（(28000-10000-15000)=3000）；其余案件路由不变。
- 断言：回归报告能列出「变更前后 payable/route 差异表」，E-A 差异 -5000，无未预期回归。

## 自测顺序建议

1. 先过 **U-1 测算**（这是整个系统正确性的地基，错了后面全错）。
2. 再 U-2/U-3/U-4/U-5，确认规则/检索/脱敏各自对。
3. N 系列确认节点契约。
4. E 系列跑通五分支（`core/app.py`）。
5. H 系列验 HITL + 持久化。
6. 最后叠 `obs/`，过 O 系列。

> 每层不过不进下一层。卡住把实际输出贴出来，对照"期望"列定位。
