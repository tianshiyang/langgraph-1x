# 需求规格说明书 (SRS) · 保险理赔智能审核 Agent

> 面向开发。本文定义**做什么、数据长什么样、每条规则怎么判、验收线在哪**。

## 0. 术语表（避免歧义）

| 术语 | 定义 |
| --- | --- |
| 案件 Claim | 一次理赔申请的完整生命周期实体，主键 `claim_id` |
| 材料 Material | 案件下的一份凭证（发票/病历/费用清单/诊断证明/身份证/银行卡） |
| 抽取 Extract | 用 LLM 把材料图片/文本转成**结构化字段**（本项目用文本 mock，不做真 OCR） |
| 免赔额 Deductible | 年度累计、需先自行承担的金额；本产品 10000 元 |
| 报销比例 Rate | 免赔额以上部分的赔付比例；本产品有社保 100% |
| 保额余额 Remaining | `sum_insured - used_amount`，本次赔付上限 |
| 等待期 Waiting | 保单生效后一段时间内出险不赔；本产品 30 天 |
| 既往症 Pre-existing | 投保前已存在的疾病，条款除外 |
| HITL | Human-in-the-loop，人工核赔审批 |
| 直赔 Auto-pay | 系统自动通过并出具赔付结论，无需人工 |

## 1. 系统上下文

```
        ┌───────────────────────────────────────────────┐
        │            理赔智能审核 Agent (LangGraph)         │
        │  立案→抽取→校验→保单核对→(条款∥反欺诈)→测算→决策    │
        └───────────────────────────────────────────────┘
          │            │              │            │
      读/写业务库    向量检索        调用大模型     观测/评估
          ▼            ▼              ▼            ▼
     Postgres      Milvus         GLM(provider)  Langfuse
   (clm_* 业务表) (条款/案例库)   (抽取/话术/裁判)  (trace/score/prompt)
```

- **确定性边界（重要，行业标准）**：**涉及金额与准入的判断，一律由确定性代码计算，LLM 只负责"从材料里抽字段"和"把结论写成话术"**。理由：赔付金额可复算、可审计、可回归，不能依赖模型的不稳定输出。详见 `Agent设计.md` §2。

## 2. 数据契约（运行时，开发按此定义类型）

> 业务表 DDL 见 `README.md` §5.1。这里定义**图在内存里流转的数据结构**，是节点间的接口。全部建议用 `TypedDict` / `pydantic`，字段带中文注释。

### 2.1 图状态 `ClaimState`（单一数据源）

| 字段 | 类型 | 写入节点 | 含义 |
| --- | --- | --- | --- |
| `claim_id` | `str` | 入参 | 案件号（也是 checkpointer thread_id、Langfuse session_id） |
| `claim` | `dict` | intake | `clm_claims` 行快照 |
| `policy` | `dict` | intake | `clm_policies` 行快照 |
| `insured` | `dict` | intake | `clm_insureds` 行快照（PII 原文仅在内存，上报前脱敏） |
| `materials` | `list[MaterialInput]` | intake | 待抽取材料列表 |
| `extracts` | `list[MaterialExtract]`（reducer 合并） | extract(并行) | 每份材料的结构化抽取结果 |
| `validation` | `Validation` | validate | 完整性/一致性校验结果 |
| `policy_check` | `PolicyCheck` | policy_check | 保单核对结果（准入 blockers） |
| `clause_evidence` | `list[ClauseEvidence]` | clause_match | 命中的适用条款证据 |
| `fraud` | `FraudResult` | fraud(子图) | 反欺诈风险等级与信号 |
| `settlement` | `Settlement \| None` | settle | 赔付测算明细（可复算） |
| `decision` | `Decision \| None` | decide | 路由 + 应赔额 + 依据 |
| `adjuster_action` | `AdjusterAction \| None` | human_review(resume 注入) | 核赔员裁决 |
| `result` | `ClaimResult \| None` | auto_pay/reject/finalize | 最终结论文书 |
| `events` | `list[Event]`（reducer 追加） | 所有节点 | 审计事件流 |

### 2.2 子结构

```python
# 材料输入
MaterialInput = TypedDict("MaterialInput", {
    "material_id": str,      # 材料 ID
    "type": str,             # 发票/病历/费用清单/诊断证明/身份证/银行卡
    "content": str,          # mock：材料的文本内容（真实系统是 file_uri + OCR）
})

# 单份材料抽取结果
class MaterialExtract(TypedDict):
    material_id: str         # 材料 ID
    type: str                # 材料类型
    fields: dict             # 结构化字段（见下方各类型 schema）
    status: str              # 已抽取 / 异常
    error: str | None        # 异常原因（容错兜底时非空）

# 各材料类型的 fields 约定（LLM 结构化输出目标）
# 发票:     {invoice_no, total_amount:float, invoice_date:"YYYY-MM-DD", hospital}
# 费用清单:  {items:[{name, amount:float}], sum_amount:float}
# 诊断证明:  {diagnosis, visit_date:"YYYY-MM-DD", hospital, admit_date?, discharge_date?}
# 身份证:    {name, id_no}
# 银行卡:    {bank, card_no}

class Validation(TypedDict):
    complete: bool                    # 必需材料是否齐全
    missing: list[str]                # 缺失的材料类型
    inconsistencies: list[str]        # 一致性问题描述

class PolicyCheck(TypedDict):
    in_force: bool                    # 保单是否有效且在保障期
    passed_waiting: bool              # 是否已过等待期
    preexisting_excluded: bool        # 是否命中既往症除外
    deductible: float                 # 免赔额
    rate: float                       # 报销比例
    remaining_sum: float              # 保额余额
    blockers: list[str]               # 准入拦截原因（非空→拒赔）

class ClauseEvidence(TypedDict):
    clause_no: str                    # 条款号
    category: str                     # 报销比例/免赔额/除外责任/等待期/保障范围
    text: str                         # 条款原文片段
    score: float                      # 检索相似度

class FraudResult(TypedDict):
    risk_level: str                   # 低/中/高
    signals: list[dict]               # [{rule, hit:bool, detail}]
    similar_cases: list[dict]         # [{summary, label, score}]

class Settlement(TypedDict):          # 每一项都要能复算
    invoice_total: float              # 发票总额
    social_paid: float                # 社保已报销
    excluded: float                   # 条款除外金额
    reasonable: float                 # 合理医疗费用
    deductible: float                 # 免赔额
    rate: float                       # 报销比例
    payable_before_cap: float         # 封顶前应赔
    remaining_sum: float              # 保额余额
    payable: float                    # 最终应赔

class Decision(TypedDict):
    route: str                        # auto_pay / human_review / reject
    payable: float                    # 建议应赔额
    risk_level: str                   # 低/中/高
    reason: str                       # 决策依据（自然语言）
    clause_refs: list[str]            # 引用条款号

class AdjusterAction(TypedDict):      # HITL resume 注入
    action: str                       # approve / adjust / reject / return
    amount: float | None              # adjust 时的核定金额
    reason: str | None                # reject / return 时的说明
    adjuster_id: str                  # 核赔员

class Event(TypedDict):
    step: str                         # 步骤名
    actor: str                        # agent / 核赔员ID
    action: str                       # 动作
    detail: str                       # 详情
    at: str                           # 时间戳（外部注入，避免图内不确定性）

class ClaimResult(TypedDict):
    decision: str                     # 通过/部分通过/拒赔
    approved_amount: float            # 核定赔付
    letter: str                       # 赔付通知/拒赔说明文书
    clause_refs: list[str]            # 条款依据
```

## 3. 功能需求（FR）与验收标准

> 每条 FR 都给**可判定的验收标准（AC）**，测试用例逐条对应（见测试文档）。

### FR-1 立案装载 `intake`
- **描述**：按 `claim_id` 从业务库读取案件、保单、被保险人、材料，装入 `ClaimState`。
- **AC-1.1** 给定有效 `claim_id`，state 中 `claim/policy/insured` 非空，`materials` 数量等于库中该案件材料数。
- **AC-1.2** `claim_id` 不存在时，抛业务异常并记一条 `events`（step=intake, action=案件不存在），不进入后续节点。

### FR-2 材料抽取 `extract`（并行）
- **描述**：对 `materials` 中每份材料**并行**调 LLM 抽取结构化字段（§2.2 schema），合并进 `extracts`。
- **AC-2.1** N 份材料产出 N 条 `MaterialExtract`，`material_id` 一一对应。
- **AC-2.2** 单份材料抽取异常（模型报错/超时）时，该条 `status="异常"`、`error` 非空，**其余材料不受影响，流程不崩**。
- **AC-2.3** 抽取节点对可重试错误自动重试（策略见 `Agent设计.md` §6），重试仍失败才降级为异常兜底。

### FR-3 校验 `validate`
- **描述**：按业务规则 BR-1/BR-2 判定完整性与一致性。
- **AC-3.1** 缺任一必需材料 → `complete=False` 且 `missing` 列出缺失类型。
- **AC-3.2** 金额/日期/姓名不一致 → `inconsistencies` 记录具体问题。
- **AC-3.3** `complete=False` 或存在阻断性不一致 → 路由到"待补件"，不进入保单核对。

### FR-4 保单核对 `policy_check`
- **描述**：按 BR-3/BR-4/BR-5 判定准入，读出测算参数。
- **AC-4.1** 保单失效/不在保障期 → `blockers` 含"保单未生效或已失效"。
- **AC-4.2** 出险日在等待期内 → `passed_waiting=False`，`blockers` 含"等待期内出险"。
- **AC-4.3** 诊断命中既往症除外 → `preexisting_excluded=True`，`blockers` 含"既往症除外"。
- **AC-4.4** `deductible/rate/remaining_sum` 与保单一致。

### FR-5 条款匹配 `clause_match`（Milvus）
- **描述**：以"险种+诊断+费用类型"检索适用条款，产出 `clause_evidence`。
- **AC-5.1** 检索按 `product` 元数据过滤，不返回其他险种条款。
- **AC-5.2** 至少命中免赔额、报销比例两类条款证据（供决策引用）。
- **AC-5.3** 检索为空时不报错，`clause_evidence=[]` 并记事件（供人工关注）。

### FR-6 反欺诈 `fraud`（子图）
- **描述**：按 BR-7 综合规则信号 + Milvus 相似案例，输出风险等级。
- **AC-6.1** 命中"短期多次"需依据**长期记忆(store)**中该被保险人历史，而非仅当前案件。
- **AC-6.2** 相似案例检索命中 `label∈{欺诈,存疑}` 且 `score≥0.8` → 风险升"高"。
- **AC-6.3** `signals` 完整记录每条规则命中与否及 detail（可解释）。

### FR-7 赔付测算 `settle`
- **描述**：按 BR-6 公式计算 `Settlement`，每项可复算。
- **AC-7.1** `payable` = `min(max(0, reasonable - deductible) * rate, remaining_sum)`，与手算一致。
- **AC-7.2** `Settlement` 各中间项（reasonable/payable_before_cap 等）全部落库，供审计复算。
- **AC-7.3** 测算由**确定性代码**完成，不经过 LLM。

### FR-8 决策路由 `decide`
- **描述**：按 BR-8 用 `Command(goto, update)` 三分支路由。
- **AC-8.1** `blockers` 非空 → `route="reject"`。
- **AC-8.2** `payable≤10000` 且 `risk_level="低"` 且校验全过 → `route="auto_pay"`。
- **AC-8.3** 其余 → `route="human_review"`。
- **AC-8.4** `decision.reason` 与 `clause_refs` 非空且能对应到实际命中条款。

### FR-9 人工核赔 `human_review`（HITL）
- **描述**：转人工案件在此 `interrupt`，展示证据包，接收核赔员裁决后 resume（BR-9）。
- **AC-9.1** interrupt 载荷含：应赔额、`Settlement` 明细、`clause_evidence`、`fraud.signals`、关键抽取字段。
- **AC-9.2** `approve` → 按 Agent `payable` 出具；`adjust` → 按核赔员 `amount` 出具且记差异；`reject` → 拒赔；`return` → 回"待补件"。
- **AC-9.3** 进程重启后凭 `claim_id` 能恢复到中断点继续。

### FR-10 出具结论 `auto_pay / reject / finalize`
- **描述**：生成结论文书（LLM 写话术），落库 `approved_amount/decision/decision_reason`，写审计事件。
- **AC-10.1** 通过类结论含金额与条款依据；拒赔结论含被拒条款号与通俗解释。
- **AC-10.2** 落库后 `clm_claims.status` 更新为 已赔付/已拒赔/待补件之一。

### FR-11 观测与评估（Langfuse）
- 见 [`Langfuse埋点规范.md`](./Langfuse埋点规范.md) 与 [`测试用例与期望.md`](./测试用例与期望.md) §6。

## 4. 业务规则（BR）— 可测试的精确表述

| 编号 | 规则 | 精确判定 |
| --- | --- | --- |
| BR-1 | 必需材料 | 住院报销必需 `{发票, 费用清单, 诊断证明}`；缺任一 → 不完整 |
| BR-2 | 一致性 | ① 发票 `total_amount` == 清单 `sum_amount`（容差 0）；② 发票/诊断日期落在案件就诊区间；③ 证件 `name` == `policy.insured.name` |
| BR-3 | 保单有效 | `policy.status=="有效"` 且 `effective_date ≤ incident_date ≤ expiry_date` |
| BR-4 | 等待期 | `incident_date ≥ effective_date + waiting_days`，否则拒赔 |
| BR-5 | 既往症 | `diagnosis` 命中 `preexisting_note`（关键词或 LLM 判定）→ 拒赔 |
| BR-6 | 测算 | `reasonable = invoice_total − social_paid − excluded`；`payable = min(max(0, reasonable − deductible) × rate, remaining_sum)` |
| BR-7 | 反欺诈 | 信号：①90天内已结案≥2次 ②单次申报>10万 ③机构/被保险人命中名单 ④相似欺诈案例 score≥0.8。命中≥2 或命中④ → 高；命中1 → 中；0 → 低 |
| BR-8 | 路由 | `blockers` 非空→拒赔；`payable≤10000 且 风险=低 且 校验全过`→直赔；否则→人工 |
| BR-9 | HITL | approve/adjust/reject/return 四动作，语义见 FR-9 |

**阈值集中管理**：`deductible=10000`、`auto_pay 上限=10000`、`大额=100000`、`相似欺诈阈值=0.8`、`短期窗口=90天` 全部放一个 `config`/常量模块，评估时可改（回归用）。

## 5. 非功能需求（NFR）

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| NFR-1 合规留痕 | 每步产出 `events` + Langfuse span | 任一已结案案件可还原全过程与依据 |
| NFR-2 PII 脱敏 | 身份证/银行卡/手机号/邮箱上报前打码 | Langfuse UI 中查不到明文 PII |
| NFR-3 可复算 | 金额由确定性代码算，明细落库 | 用 `Settlement` 能手工复算出 `payable` |
| NFR-4 可恢复 | checkpointer 持久化，thread=claim_id | 进程重启后案件可续跑 |
| NFR-5 幂等 | 建表/种子/灌向量可反复执行 | 重复执行不产生脏数据 |
| NFR-6 分层可独立运行 | `core/app.py` 不依赖 Langfuse | 断网 Langfuse 仍能完成审核 |
| NFR-7 成本可见 | generation 记录 token；配 glm 定价 | trace 成本非 0 |

## 6. 边界与异常处理

| 场景 | 期望行为 |
| --- | --- |
| `claim_id` 不存在 | 抛业务异常，记事件，不进流程（AC-1.2） |
| 材料抽取超时/报错 | 重试→仍失败则该材料标异常兜底，流程继续（AC-2.2/2.3） |
| Milvus 检索为空/超时 | `clause_evidence=[]`，记事件，转人工（不得静默通过） |
| LLM 结论话术生成失败 | 用模板兜底文书，金额与决策不受影响 |
| 保额余额不足本次应赔 | `payable` 封顶到 `remaining_sum`（BR-6） |
| 核赔员 `adjust` 金额 > 应赔 | 允许但记差异事件（人工有最终裁量权），审计可见 |

## 7. 范围外（本期不做）

- 真实 OCR / 图片解析（用文本 mock 材料内容）。
- 真实支付/打款、发票查验对接。
- 权限/账号体系、Web 前端（脚本 + Langfuse UI 即界面）。
- 多险种混合（先只做住院医疗，意外医疗为进阶）。
